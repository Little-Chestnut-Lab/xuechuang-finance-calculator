公开版权署名：Little Chestnut Lab

**版本：v0.1.0 公开测试版｜面向学创杯财务赛道参赛者｜个人开发的非官方辅助工具**

本工具用于在现有规则范围内录入经营决策，进行四季度连续测算，查看预算填报参考、利润税费、FIFO成本和现金结算。由使用者输入经营决策和实际出单量，程序据此计算；不预测竞争分单，不提供最优经营策略。

本项目为非官方辅助工具，模板参数根据公开信息整理。部分特殊计算规则尚未完全验证，实际比赛结果请以官方平台为准。

本公开测试版包含八套模板参数、预算参考、全部已实现计算功能与完整空白自录规则模块。采用PolyForm Noncommercial License 1.0.0非商业许可，具体说明见下文；发布前待维护者确认的事项见[待办清单](RELEASE_CHECKLIST.md)。

## 下载与运行

1. 将项目ZIP下载到电脑并完整解压。不要直接在压缩软件预览窗口中使用。
2. 在templates目录双击任意“方案计算器.html”；自录版打开custom目录的“通用计算网页.html”。在GitHub文件页面直接查看HTML会显示源码，需要下载文件或下载ZIP后运行。
3. 使用桌面Edge打开。本次验收环境为Edge；其他浏览器兼容情况见[测试说明](TESTING.md)。普通离线使用不需要Node、npm、账号或计算服务器。
4. 首次新建为**空白建设和经营输入**，没有个人经营预设。八模板版保留正常模板参数、规则订单及上限报价；自录版先填写规则。

index.html是模块维护入口，需要同目录的JS和CSS文件；完整“方案计算器.html/通用计算网页.html”已内嵌这些内容。开发者不要只复制index.html。完整项目保留两种形式，未迁移框架或重写引擎。

## 八模板版：录入一局

1. 在顶部“规则模板”选择实际对局模板，在“本局记录”填写便于辨认的名称。每个模板的本局记录分别保存。
2. 点击季度卡片或季度按钮，选择要编辑的季度。使用“＋ 本季新增厂房”“＋ 本季新增生产线”，填写取得方式、型号、所属厂房与季度。在“配套工人”核实招聘季度及工人数。
3. 在“逐线生产”录入实际产量；产量留空表示按设备与已招工人能力满产。上下移动生产线改变当季投产顺序，会影响不同批次FIFO；订单区的“调整顺序”仅改变展示排列，两者不要混淆。
4. 在经营区选择“交单前预计”或“交单后实际”，填写小组数、短/长贷、销售招聘、广告、提交上限和出单数量。**出单数量必须由使用者按平台预计或实际分单录入**，切换“实际”不会自动取得平台数据。固定市场订单和手工订单可编辑字段不同，请按实际界面使用。
5. 如分批交货，在“分批交货”填各批数量，例如`1,2`，合计须等于该单交货量。程序依此生成票据；零账期直接收款。贴现区选择具体票据及交单前/交单后时点，同一张票据不能重复贴现。
6. 查看页面错误和提示，再查看“预算填报参考”“利润与税费”“真实现金与到期项目”“FIFO与批次成本”。第一处无法计算的季度会影响后季，不要把未生成结果当作0。
7. 交单前点击“保存本季预算快照”。后续修改实际数量会重算当前账本，已保存快照继续保留。预计/实际是同一份经营数据的阶段标记，不是两套独立计划。
8. 每季结算后导出本局记录。第四季还要查看第五季初最终结算现金；第五季初是结算点，不是新增的经营季度。

“选择另一套建设安排”目前仅保留空白建设选项，私人策略预设已移除。日常按实际安排逐季添加资产即可，不必点击该控件。需要新开一局时使用“重置本局”；“撤销重置”只恢复最近一次重置前记录，不能代替长期备份。

## 完整自录规则版

1. 打开custom完整HTML，进入“规则录入”。填写规则名称、初始现金、厂房、设备、工人、销售、原料、贷款、贴现、税费和四季市场订单。
2. 规则金额和数量按页面单位填写。百分比框填`5`表示5%；真实零值明确填0，空白不当作0。当前模型仍是固定产品/设备类别和四季度口径，不能据“自录”理解为支持任意业务模型。
3. 点击“保存规则并开始计算”。有缺项时按页面提示补齐。已有有效规则后，按钮为“应用规则变更并重算”。草稿自动保存，但只有应用后才改变当前计算规则。
4. 进入计算页后按前述流程录入经营。规则区的“导出规则/导入规则”用于复用配置；导入规则先进入草稿，需要应用才生效。
5. 用“导出完整备份”或计算页“导出本局记录”保存整个工作区；用“恢复完整备份”或计算页“导入本局记录”恢复。不要把仅规则文件当作完整经营备份。

## 保存、导入、导出与JSON备份

| 功能 | 保存内容 | 能否作为恢复用备份 |
|---|---|---|
| 八模板“导出本局记录” | 当前模板的建设、四季经营、票据选择、排序、快照等 | 可以，使用“导入本局记录” |
| 八模板“导出计算明细” | 参数、输入与计算结果，用于核对 | 不等同可恢复的本局记录 |
| 自录“导出规则” | 已保存规则或尚未保存的规则草稿 | 只恢复配置，不恢复整局 |
| 自录“导出完整备份”/计算页“导出本局记录” | 规则、草稿、本局、版本及撤销数据 | 可以，使用自录完整恢复功能 |
| “导出导入前备份” | 最近导入前保留的备份 | 有正常备份时可导出后恢复；无备份会提示 |

修改输入后页面会重算并尝试保存到浏览器localStorage，请留意保存状态。**本机浏览器保存不是云备份，HTML文件本身也不携带你的局记录。** 清理浏览器数据、无痕模式、存储被拒绝、换浏览器/电脑或移动HTML路径，都可能导致看不到旧记录。

建议每季结束导出一个带模板和季度标记的JSON，并在独立私人位置另存一份；先导出再换文件。恢复时先选择对应版本：八模板局记录、自录完整备份和规则文件不能混用。新版导入会先校验和备份；失败时尽量恢复，但浏览器持续拒绝写入时仍需依靠你自己的备份。

不要把自己的JSON保存在公开仓库。它可能含资产、销量、广告、融资及策略；“已经清理软件默认数据”不表示用户自行导出的数据自动脱敏。`.gitignore`只帮助防止意外提交，不会自动保护已上传的文件。

## 当前报表和测算视图

| 视图 | 实际内容 |
|---|---|
| 预算填报参考 | 全面预算、现金预算的原表行序与已实现映射，部分项目仍待人工核对 |
| 利润与税费 | 利润表项目、增值税及附加、所得税和亏损等参考 |
| 真实现金与到期项目 | 季初、交单前估算、交货/贴现后、期末及下季初现金；票据/应付等台账 |
| FIFO与批次成本 | 各批成本构成、销售成本结转及期末批次 |

这些视图不等同四张完整法定财务报表；没有完整法定资产负债表或法定现金流量表生成能力。预算填报口径与真实现金收付时点不同，不能把预算收支合计直接当作现金余额。灰色自动合计和无后续影响的辅助空白，不自动等于需要人工填报的错误。

## 适用范围与反馈

精度、紧急贷款、闲置线、特殊税务、贷款额度和部分预算行等限制详见[KNOWN_ISSUES.md](KNOWN_ISSUES.md)。程序保留BigInt高精度、FIFO和跨季度计算，但**不保证所有经营情形均与官方平台一致**。使用者仍须核对规则、实际出单、现金阶段和平台结果。

仓库正式建立并开启Issues后，在GitHub的“Issues → New issue”选择“计算错误反馈”或“功能建议”。提供版本号、模板、季度/阶段、财务项目、双方结果、最小脱敏输入及复现步骤。不要公开账号、队伍信息、私人完整经营方案或未经允许传播的截图/资料。参见[CONTRIBUTING.md](CONTRIBUTING.md)。本公开测试版没有附带在线反馈系统，也没有预设虚构仓库地址。
